## Proposed normalization boundary

Keep provider adaptation in the server boundary before calling `packages/routing/src/costs.ts`. The pure package accepts a single latest **cumulative per-turn** snapshot with inclusive input, inclusive output, explicit cache reads/writes and optional reasoning subset. Never pass native thread totals, context occupancy or response deltas directly. The caller replaces its previous row for the same durable turn; it does not add repeated snapshot prices. Lower corrected totals replace higher ones. Durable identity, transactional replacement and replay tests belong to step 2.

For Claude, retain the existing segment accumulation and inclusive input transformation. Resolve omitted cache counters only with documented provider semantics; otherwise keep cost unknown even if the upstream usage status says complete. For Codex, retain thread-total-to-turn accumulation, preserving absent cache-write counters as unknown. For OpenCode, add native reasoning to output once before this boundary; adding it again here double-counts. For ACP, propose explicit unavailable turn usage until a flavor supplies documented billable buckets; do not infer them from context usage or treat missing counters as zero. These are proposals, not changes to upstream adapters.

`priceTurnUsage` derives `uncachedInput = input - read - write`, preserving disjoint read/write/output buckets. It rejects non-integer, negative, non-finite, unsafe and inconsistent counters rather than clamping. Missing required buckets or unavailable usage produces null USD. Reasoning may be absent because inclusive output remains priceable; if present it must not exceed output. A partial snapshot with all buckets has a provisional estimate with `complete: false`; a partial snapshot missing buckets has no total estimate. Unknown rates preserve known tokens and return `priced: false`, null USD. Budget reconciliation must require both `complete` and `priced`.

Rate lookup, aliases, overrides and rate-version pinning stay outside the pure arithmetic function. Pass a resolved immutable USD-per-million rate record or null; no T3 imports, live pricing, currency conversion, provider-reported charge or subscription-window estimate enters it. Unknown rates never become free. `apps/server/src/usage/usagePricing.ts` similarly prices disjoint buckets and inclusive output, but its existing unpriced numeric-zero convention is not used for this proposed ledger API.
